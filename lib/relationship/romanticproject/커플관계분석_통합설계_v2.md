## 1. 콘텐츠 구조 병합안 — 기존 리포트 강점 + 이전 제안 통합

### 1-1. 기존 리포트(Aha It's me!)에서 반드시 유지해야 할 강점

| 요소 | 왜 좋은가 |
|---|---|
| **상황별 지수 분리** (썸·데이트 / 일상·미래 / 갈등·긴장) | 단일 궁합 점수보다 훨씬 입체적. "우리는 평소엔 좋은데 싸울 땐 왜 이럴까"라는 실제 고민에 정확히 대응 |
| **호감·케미·예민 3축 게이지** | 상황마다 재사용되는 공통 축이라 비교가 쉽고 직관적 |
| **1인칭 성향 카드 + 은유적 별명** ("든든한 산", "타오르는 불꽃") | 감성적 몰입도 최고. 사용자가 캡처해서 공유하고 싶어지는 요소 |
| **A→B, B→A 양방향 서술** | "내가 상대에게 주는 것"과 "상대가 나에게 주는 것"을 분리 — 요청하신 "내가 얻는 장점" 항목의 근거 구조로 그대로 활용 가능 |
| **갈등 대사 Before/After 테이블** | 가장 실용적인 파트. 재구매·공유 유도력이 가장 높을 구간 |
| **시간 흐름 타임라인** (지금→3년→5년→10년) | 사주의 대운(大運) 개념을 자연스럽게 활용한 좋은 장치 |

### 1-2. 기존 리포트에 빠져있던 것 (제 이전 제안에서 보강)

- **강점/약점을 명시적으로 분리한 섹션이 없음** — 지금은 "관계가 특별한 이유"에 장점만 녹아있고, "이 사람과 있으면 약해지는 지점"이 없음. 사용자가 명시적으로 요청한 항목이므로 **반드시 별도 섹션화** 필요
- **케미가 "감정" 축 위주** — 소통(대화) 케미, 신체적 케미가 분리되어 있지 않음
- **최종 요약/공유용 카드가 없음** — 타임라인에서 그냥 끝남. 저장하고 싶은 한 장 요약이 필요
- **심리 10축 데이터가 시각화되지 않음** — 지금은 서사 텍스트로만 녹아있는데, 레이더 차트 하나로 "데이터 기반 신뢰감"을 크게 올릴 수 있음

### 1-3. 병합 최종 구조 (권장 목차)

```
0. 커버 — 한줄 요약 + 궁합 등급(A~F) + 관계 유형 네이밍
1. 관계 지수 대시보드 — 상황별 3축 게이지 (기존 유지)
2. 우리는 왜 끌렸는가 — 사주 서사 + 심리 매칭 서사 (기존 "숨은 마음" 확장)
3. 서로의 기질 카드 — 1인칭 서술(기존) + 심리 10축 레이더 차트(신규)
4. 서로 비교표 — 심리 10축 기반으로 재설계 (기존 6항목 → 데이터 근거 강화)
5. 케미스트리 심화 — 감정 / 소통 / 신체 3분리 (신규)
6. 이 관계가 특별한 이유 — A→B, B→A (기존 유지)
7. 갈등 지도 — 트리거→반응→확대/완화 순환구조 다이어그램(신규) + 대사 Before/After(기존)
8. 강점 · 약점 — "내가 얻는 것" vs "함께 있으면 약해지는 것" (신규, 사용자 요청 핵심)
9. 서로에게 도움되는 행동 — 사람별 액션 + 대사 예시 (기존 유지)
10. 타이밍 — 대운/세운 기반 시간 흐름 (기존 확장)
11. 최종 요약 카드 — 공유용 한 장 요약 (신규)
```

## 2. 사주 해석 로직 설계

관계 분석에서 사주가 답해야 할 질문은 명확히 4가지로 나뉩니다: **① 왜 끌렸는가, ② 서로에게 어떤 존재인가, ③ 어디서 부딪히는가, ④ 언제 흐름이 바뀌는가.** 각 사주 요소를 아래처럼 질문별로 배치하면 로직이 깔끔해집니다.

### 2-1. 사주 요소 → 해석 규칙 → 활용처 매핑표

| 사주 요소 | 이게 상징하는 것 | 해석 규칙 예시 | 리포트 활용 섹션 |
|---|---|---|---|
| **일간(日干)** | 나의 본질, 자아 | 일간의 오행(木火土金水)에 따라 기본 기질 문장 생성 (예: 木일간 → "뻗어나가려는 성장 지향") | 3. 기질 카드 |
| **일지(日支)** | 배우자궁 — 관계 속 나의 태도 | 일지 오행/특성에 따라 "관계 안에서 보여지는 나의 모습" 문장 생성 (예: 조용히 곁을 지키는 유형 vs 적극적으로 표현하는 유형) | 3. 기질 카드, 2. 왜 끌렸는가 |
| **지장간(支藏干)** | 일지 속 숨겨진 천간 — 겉으로 안 드러나는 내면 | 지장간에 있는 십성(정관/편재 등)에 따라 "겉과 속이 다른 지점" 문장 생성 | 2. 숨은 마음 |
| **십성 관계** (두 사람 일간 비교) | 관계의 역학 구조 | 비겁↔비겁: 대등·경쟁 / 식상↔인성: 감정소모 주의 / 정재↔정관: 안정적 역할분담 / 편관↔편인: 강한 끌림+긴장 공존 등 조합별 규칙 사전 정의 | 2. 왜 끌렸는가, 6. 특별한 이유 |
| **오행 상생·상극** | 기운의 순환 | 상생(木生火 등) → 케미 점수 가산 + "서로를 자연스럽게 키워주는 조합" 서술 / 상극(木剋土 등) → 예민 점수 가산 + "긴장이 성장의 자극이 되는 조합" 식으로 중립적 프레이밍 | 5. 케미스트리, 1. 지수 산출 근거 |
| **합(合)** (지지 간) | 편안함, 결속 | 년/월/일/시 지지 간 합이 있으면 해당 영역(썸/일상/갈등) 지수 가산 | 1. 상황별 지수 산출 |
| **충·형·파·해(沖刑破害)** | 마찰, 긴장 | 일지-일지 충이면 갈등 상황 예민 점수 강하게 가산 + 7. 갈등 지도의 "기질적 마찰 지점" 서술 근거 | 7. 갈등 지도 |
| **도화살(桃花殺)** | 매력, 이성 끌림 지수 | 보유자는 호감 축 가산 + "매력적으로 보여지는 존재" 서사 | 1. 호감 지수, 2. 왜 끌렸는가 |
| **역마살(驛馬殺)** | 변화, 이동 기운 | 자극추구 심리축과 크로스체크 — 둘 다 있으면 "함께 있을 때 새로운 걸 시도하고 싶어지는 조합" | 5. 케미스트리 |
| **화개살(華蓋殺)** | 몰입, 고독 선호 | 있으면 "혼자만의 시간이 필요한 유형" — 심리축 energy_style(내향)과 크로스체크해 일관되면 신뢰도 있는 서술로 채택 | 8. 약점 (에너지 소모 관리) |
| **대운(大運)** | 10년 단위 흐름 | 현재 대운의 오행이 두 사람 관계에 우호적(상생)인지 비우호적(상극)인지로 "지금이 좋은 시기인지" 판단 | 10. 타이밍 |
| **세운(歲運)** | 연 단위 흐름 | 특정 해의 간지가 두 사람 사주와 합/충 관계면 "주의 시기" 또는 "도약 시기"로 플래그 | 10. 타이밍 |

### 2-2. 설계 원칙

1. **십성 조합표를 먼저 코드화**: 10가지 십성(비견/겁재/식신/상관/편재/정재/편관/정관/편인/정인) × 10가지 조합 = 관계 역학 문장 뱅크를 미리 만들어두고, 계산된 조합에 따라 문장을 뽑아 쓰는 구조가 가장 안정적입니다.
2. **합/충은 지수 가감 로직으로**: 서사(텍스트)보다는 **점수 보정치**로 우선 활용하고, 임계값을 넘을 때만 텍스트 서술에 반영 (예: 일지 충이 있을 때만 "기질적으로 부딪히는 지점" 문장 노출)
3. **신살은 보조 조미료로만**: 도화살/화개살 등은 남용하면 "사주 앱스러움"이 강해져서 신뢰도가 떨어집니다. 호감/매력 관련 서사 1곳에만 제한적으로 사용 권장.
4. **대운/세운은 사주만의 고유 자산**: 심리 스코어로는 절대 줄 수 없는 "시간축 예측"이므로, 타이밍 섹션은 사주 로직에 확실히 무게를 실어야 차별화가 명확해집니다.

## 3. 행동심리 10축 스코어 통합 로직

주신 10개 축을 정리하면 아래와 같습니다. 각 축을 **개인 서술용**과 **매칭(2인 비교) 연산용**으로 나눠 설계했습니다.

### 3-1. 축 정의 및 활용

| 축 | 낮음(0) ↔ 높음(100) | 개인 서술 활용 | 매칭 연산 활용 |
|---|---|---|---|
| `stimulation` 자극추구 | 안정 선호 ↔ 새로움 선호 | 데이트 취향 서술 | 둘 다 높음=권태 없지만 안정성 부족 리스크 / 둘 다 낮음=편안하지만 권태 리스크 / 격차 큼=한쪽이 끌고가는 구조 → 갈등 트리거 후보 |
| `self_control` 자기통제 | 감정 표출형 ↔ 감정 조절형 | 스트레스 반응 서술 | 둘 다 낮음=갈등 시 감정 격화 위험 높음 → 갈등 지도 핵심 변수 |
| `practicality` 현실실리 | 낭만/의미 중시 ↔ 실용/효율 중시 | 가치관 서술 | 격차 큼=소비·데이트 방식 갈등 후보 |
| `structure` 계획구조화 | 즉흥형 ↔ 계획형 | 일상 스타일 서술 | 격차 큼=여행/약속 방식 갈등 후보, 서로비교표의 "의사결정" 항목과 연동 |
| `empathy` 관계공감 | 논리 중심 ↔ 정서 공감 중심 | 소통 스타일 서술 | 한쪽만 낮음=정서적 미스매치("내 얘기를 안 들어주는 것 같다") 리스크 |
| `conflict_style` 갈등대응 | 회피형 ↔ 직면형 | 갈등 시 행동 예측 | **7. 갈등 지도의 핵심 엔진.** 회피+회피=문제 누적형 / 직면+직면=격화형 / 회피+직면=추적-회피 패턴(한쪽은 캐묻고 한쪽은 침묵) |
| `resilience` 회복탄력성 | 회복 느림 ↔ 회복 빠름 | 회복력 서술 | 평균 낮음=다툰 뒤 냉전 장기화 예측 / 평균 높음=빠른 화해 예측 |
| `recognition` 인정욕구 | 낮음 ↔ 높음 | 애정표현 니즈 서술 | 한쪽만 높음="표현을 더 자주 해줘야 하는 상대" → 9. 액션플랜 근거 |
| `energy_style` 에너지방식 | 내향(혼자 충전) ↔ 외향(같이 충전) | 재충전 방식 서술 | 반대 조합=데이트 빈도·개인시간 갈등 후보 |
| `thinking_style` 사고방식 | 직관형 ↔ 분석형 | 대화 스타일 서술 | 반대 조합=대화 중 오해 발생 지점("결론부터 말해" vs "과정도 듣고싶어") |
| `decision_style` 의사결정방식 | 즉흥형 ↔ 신중형 | 결정 방식 서술 | 반대 조합=미래 설계(결혼, 이사 등) 논의 시 마찰 후보 |

### 3-2. 2인 매칭 연산 기본 공식

```
격차(gap) = |A축값 - B축값|

gap < 20   → "유사형" : 이해가 쉬움. 단, 두 사람 다 낮은 경우엔 "같은 약점 증폭" 경고 필요
gap 20~50  → "보완형" : 서로 다른 게 매력 포인트가 되지만 마찰 가능성도 존재
gap > 50   → "긴장형" : 명시적 갈등 트리거로 플래그, 7번 갈등 지도 섹션에 우선 노출
```

이 gap 값을 **사주의 합/충 판정과 교차 검증**하는 것이 핵심 차별화 포인트입니다.

- 사주 합(合) + 심리 유사형(gap<20) → "본능적으로도 행동적으로도 잘 맞는다"는 강한 확신 서술 가능
- 사주 충(沖) + 심리 긴장형(gap>50) → 갈등 지도 섹션에서 확신 있게 "이 지점은 두 사람 모두 인식하고 관리해야 할 지점"으로 명시
- 사주와 심리 결과가 **불일치**하는 경우(예: 사주는 상생인데 심리는 긴장형) → 이런 경우는 오히려 "타고난 기질은 잘 맞지만, 습관적으로 부딪히는 지점이 있다"는 식으로 **더 정교한 인사이트**를 만들 수 있는 지점입니다. (단순 일치보다 이런 불일치 케이스가 사실 "다른 곳에서 못 주는 인사이트"가 됨)

## 4. UX/UI 설계 — 사용자가 진짜 원하는 정보 흐름

### 4-1. 정보 위계 원칙 (기존 리포트가 이미 잘 따르고 있는 순서, 유지 권장)

```
결과(궁합등급/한줄요약) → 근거(지수·비교) → 설명(서사) → 실행(액션플랜) → 저장(요약카드)
```

### 4-2. 화면별 UI 요구사항

| 화면 | 필수 UI 요소 | 비고 |
|---|---|---|
| 커버 | 궁합 등급 배지(A~F), 관계 유형 네이밍, 한줄 요약 | 공유 시 썸네일로 쓰일 영역 — 디자인 우선순위 최상 |
| 지수 대시보드 | 탭 전환형 3-컨텍스트 게이지(썸/일상/갈등), 각 게이지 롱프레스 시 정의 툴팁 | 기존 구조 유지, 애니메이션 게이지 권장 |
| 기질 카드 | 1인칭 서술 카드 + **10축 레이더 차트**(신규) | 레이더 차트는 두 사람 겹쳐서 한 화면에 오버레이하면 "다른 점"이 시각적으로 즉시 이해됨 |
| 비교표 | 항목별 좌우 비교, gap 큰 항목은 하이라이트 색상 처리 | 데이터 기반 신뢰감의 핵심 |
| 케미스트리 | 감정/소통/신체 3개 서브 게이지 | 신규 섹션 |
| 갈등 지도 | ① 트리거→반응→확대 순환 다이어그램(신규), ② 대사 Before/After 테이블(기존) | 다이어그램은 SVG 순환형으로, 아래 대사표는 그대로 |
| 강점·약점 | 아이콘 카드형, "내가 얻는 것 3개" / "약해지는 것 3개" 좌우 배치 | 약점은 비난조 아이콘(❌등) 대신 중립 아이콘 사용 — 톤 매니저 필요 |
| 액션플랜 | 사람별 탭 전환, 각 행동에 "이렇게 말해보세요" 말풍선 | 기존 유지 |
| 타이밍 | 가로 스크롤 타임라인, 각 시점 카드에 CTA("이 시기엔 이걸 해보세요") | 기존 세로형보다 가로 스크롤이 "시간 흐름"을 더 직관적으로 전달 |
| 최종 요약 | 정사각형 공유 카드(인스타 스토리 비율 1:1 또는 9:16) 별도 렌더링 | 신규. 공유 유도 핵심 장치 |

### 4-3. 사용자가 가장 궁금해하는 것 (우선순위 재확인)

1. **"우리 잘 맞아?"** → 궁합등급 + 상황별 지수 (즉시 답)
2. **"왜 자꾸 싸워?"** → 갈등 지도 (가장 체류시간 길 것으로 예상되는 섹션)
3. **"그래서 나 뭘 해야 돼?"** → 액션플랜 (재방문/재구매 유도 섹션)
4. **"우리 앞으로 어떻게 될까?"** → 타이밍 (프리미엄 결제 전환 포인트로 유력)

이 4가지가 스크롤 최상단~중단에 배치되도록 구조를 짰습니다.

## 5. 개발 요청 스펙 (개발자 전달용)

### 5-1. 입력 데이터 스키마

```json
{
  "user_a": {
    "name": "string",
    "birth_date": "YYYY-MM-DD",
    "birth_time": "HH:mm (nullable, 없으면 기본값 12:00 처리 + 정확도 낮음 안내)",
    "birth_place": "string (nullable, 없으면 기본 좌표 처리)",
    "psych_scores": {
      "stimulation": 0-100,
      "self_control": 0-100,
      "practicality": 0-100,
      "structure": 0-100,
      "empathy": 0-100,
      "conflict_style": 0-100,
      "resilience": 0-100,
      "recognition": 0-100,
      "energy_style": 0-100,
      "thinking_style": 0-100,
      "decision_style": 0-100
    }
  },
  "user_b": { "...동일 구조" },
  "relationship_type": "인연 | 동료 | 부부 | 친구 | 가족"
}
```

### 5-2. 백엔드 계산 엔진 요구사항

1. **만세력 계산 모듈**: 생년월일시 → 년주/월주/일주/시주(간지), 지장간, 십성, 신살, 대운/세운 산출. (자체 구현 또는 검증된 만세력 라이브러리/API 연동 — 정확도가 신뢰도에 직결되므로 우선순위 높음)
2. **사주 매칭 룰 엔진**: 2-1 매핑표를 코드화한 rule-based 모듈. 입력: 두 사람의 사주 데이터 → 출력: 상생/상극 여부, 합/충 여부, 십성 조합 유형, 신살 매칭 결과
3. **심리 매칭 연산 모듈**: 3-2 공식 기반. 입력: 두 사람의 10축 점수 → 출력: 축별 gap, 유형(유사/보완/긴장), 갈등 트리거 우선순위 리스트
4. **지수 산출 모듈**: 사주 룰 엔진 결과 + 심리 매칭 결과를 가중합하여 상황별(썸/일상/갈등) 호감·케미·예민 3축 점수 산출. **가중치는 A/B 테스트로 튜닝 가능하도록 설정값(config)으로 분리** 권장
5. **콘텐츠 생성 모듈**: 위 계산 결과(구조화 데이터)를 LLM 프롬프트에 주입해 자연어 서술 생성하는 하이브리드 구조 권장. 규칙 엔진이 "무엇을 말할지" 결정하고, LLM은 "어떻게 자연스럽게 표현할지"만 담당하도록 역할 분리 — 이래야 결과 일관성과 재현성이 확보됨 (LLM에게 판단까지 맡기면 같은 궁합인데 매번 결과가 달라지는 문제 발생)

### 5-3. API 엔드포인트 (예시)

```
POST /api/relationship/analyze
  body: 위 입력 스키마
  response: 분석 결과 전체 JSON (섹션별 구조화)

GET  /api/relationship/{analysis_id}
  response: 저장된 분석 결과 조회 (히스토리 화면용)

POST /api/relationship/{analysis_id}/regenerate
  response: 동일 입력값 기반 재생성 (기존 리포트의 "다시 만들기" 대응)
```

### 5-5. 기타 개발 요청 사항

- **캐싱 정책**: 동일 입력값(생년월일시+심리점수)에 대해서는 결과 캐싱, "다시 만들기"는 명시적 재생성 요청 시에만 새로 계산 (LLM 비용 관리 및 일관성 유지 목적)
- **정확도 안내 로직**: 출생시간 미입력 시 기존처럼 배너 안내 유지, 단 시주(時柱) 의존도가 높은 항목(신살 일부 등)은 이 경우 계산에서 제외하거나 신뢰도 낮음 표기 처리 필요
- **히스토리 저장 스키마**: 분석기록 리스트용으로 `{analysis_id, relationship_type, depth(기본/심화), summary_title, created_at}` 저장
- **이미지 export**: 공유 카드용 서버사이드 이미지 렌더링(예: html-to-image, puppeteer 등) 필요 여부 결정 필요
