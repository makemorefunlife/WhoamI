# 01_Saju_System.md

## Purpose

This document defines the overall architecture of the Ahaitsme Saju System.

The purpose of the Saju System is to generate an **Innate Self Profile** from birth information.

The Saju System is not a fortune-telling engine.

Its role is to translate traditional Saju data into the Ahaitsme Human Framework so it can be compared with the Survey-based Current Self Profile.

---

# Core Concept

Ahaitsme analyzes two different versions of the user.

## Current Self

Generated from Survey.

Represents:

* current behavior patterns
* current decision patterns
* current psychological tendencies
* current lifestyle adaptation

Output:

```text
CurrentSelfProfile
```

---

## Innate Self

Generated from Saju.

Represents:

* natural tendencies
* innate behavioral preferences
* default energy patterns
* underlying decision tendencies

Output:

```text
InnateSelfProfile
```

---

## Comparison Layer

The Gap Engine compares:

```text
CurrentSelfProfile

vs

InnateSelfProfile
```

to identify:

* alignment
* conflict
* adaptation patterns
* energy leakage
* decision friction

---

```text
Birth Information
```

```text
Compatibility
```

# User Input

The user provides:

```text
birth_date

birth_time

birth_country

birth_city

timezone
```

Optional:

```text
gender
```

---

# Birth Location Resolution

System automatically resolves:

```text
latitude

longitude

timezone
```

using:

```text
birth_country

birth_city
```

---

# Time Normalization

System converts user input into the final calculation time.

Possible adjustments:

```text
timezone correction

daylight saving time

longitude correction

true solar time
```

The final value is:

```text
saju_calculation_time
```

---

# Four Pillars Calculation

A Saju calculation library is responsible for generating:

```text
year pillar

month pillar

day pillar

hour pillar
```

including:

```text
heavenly stems

earthly branches

hidden stems
```

---

# Normalized Saju

Raw library output must not be used directly.

The result must be transformed into:

```text
NormalizedSaju
```

This creates a stable internal structure regardless of which Saju library is used.

---

# Human Framework Translation

Traditional Saju concepts are not exposed directly to users.

The system translates:

```text
day master

five elements

ten gods

seasonal influence

major combinations
```

into Ahaitsme Human Framework dimensions.

---

# Official Primary Axes

All final scoring must use these six axes only.

```text
autonomy
connection
stability
growth
control
adaptability
```

Definitions:

### autonomy

Preference for self-direction and independent decision making.

### connection

Preference for relationships, belonging, and emotional connection.

### stability

Preference for predictability, safety, and consistency.

### growth

Preference for challenge, exploration, and expansion.

### control

Preference for structure, planning, and self-management.

### adaptability

Preference for flexibility and adjustment to change.

---

# Scoring Philosophy

Every profile starts from a neutral baseline.

Example:

```text
50

+

element effects

+

ten god effects

+

seasonal effects

+

relation effects

=

final score
```

All final scores must be normalized into:

```text
0 - 100
```

---

# Saju Raw Layer

All original calculation data must be preserved.

Stored separately as:

```text
saju_raw
```

Examples:

```text
day master

pillars

five elements

ten gods

hidden stems

relations
```

This layer exists for:

* debugging
* future upgrades
* premium reports
* AI interpretation

---

# Innate Self Profile

Final output generated by the Saju System.

Purpose:

```text
Represent the user's innate tendencies
using the same structure used by Survey.
```

This allows direct comparison between:

```text
Current Self

and

Innate Self
```

inside the Gap Engine.

---

# Design Principles

## Principle 1

Separate calculation from interpretation.

```text
Saju Calculation

≠

Human Interpretation
```

---

## Principle 2

Store raw data.

Never discard original Saju information.

---

## Principle 3

Use Human Framework as the translation layer.

Users should not need to understand traditional Saju terminology.

---

## Principle 4

Keep output compatible with Survey.

Current Self and Innate Self must be directly comparable.

---

## Principle 5

Primary Axes are fixed.

The following axes must never be renamed:

```text
autonomy

connection

stability

growth

control

adaptability
```
