# 05_Saju_Output_Schema.md

## Purpose

This document defines the output structure generated by the Saju Engine.

The purpose of this schema is to standardize:

* Database Storage
* API Responses
* Analysis Engine Inputs
* Future Expansion

This document does not define:

* Calculation Rules
* Human Framework Mapping
* Interpretation Logic
* Report Generation

Those responsibilities belong to separate documents.

---

# Output Layers

## Saju Engine (persistent)

The Saju Engine generates three persistent layers.

```text
Raw Saju

↓

Extended NormalizedSaju

↓

InnateSelfProfile
```

## Analysis Pipeline (derived)

Cross-profile objects are defined in this document as the **schema registry** for the full v1 pipeline.

```text
CurrentSelfProfile  (Survey — see 04_Survey_Output_Schema.md)
        +
InnateSelfProfile
        │
        ▼
gap_profile          (Rules — 01_Gap_Analysis_Rules.md)
        │
        ├─► Free Step 9: gap_profile.free_preview only
        │
        └─► Paid: gap_analysis  (LLM — 03A_Gap_Analysis_Prompt.md)
```

| Object | Type | Generator | Persist? |
|--------|------|-----------|----------|
| `gap_profile` | Deterministic profile | Gap Rules engine | Optional cache; regenerable |
| `gap_analysis` | Interpretation report | 03A LLM | Generate dynamically |
| `deep_pattern` | — | 03B | Phase D (TODO) |
| `deep_narrative` | — | 03C | Phase D (TODO) |
| `deep_self_report` | — | 03D | Phase D (TODO) |
| `deep_self_report_ui` | — | 03E | Phase D (TODO) |

Sample: `samples/gap_profile.json`, `samples/outputs/gap_analysis_result.json`

# Layer 4

## GapProfile (`gap_profile`)

Purpose:

Compare **Current Self** and **Innate Self** on the Human Framework 6 axes. Stores deltas, per-axis classification, and aggregated pattern lists.

Generated from:

```text
CurrentSelfProfile.primary_axes

+

InnateSelfProfile.primary_axes

↓

01_Gap_Analysis_Rules.md  (runtime: gap-analyzer.js)
```

Calculation rules: [01_Gap_Analysis_Rules.md](../analysis/01_Gap_Analysis_Rules.md)  
Concept reference: [11_Comparison_Framework.md](../framework/11_Comparison_Framework.md)

### Product exposure

| Field group | Free Step 9 | Paid (03A / 03D) |
|-------------|-------------|------------------|
| `free_preview` | ✓ radar + delta only | — |
| `per_axis`, `aggregated`, `primary_pattern` | ✗ do not expose labels in UI | ✓ 03A input |
| `overall_severity`, `max_abs_delta` | optional numeric hint | ✓ |

### Stored Example

```json
{
  "gap_profile": {
    "profile_type": "gap_profile",
    "version": "v1",
    "inputs": {
      "current_self_axes": {
        "autonomy": 0,
        "connection": 0,
        "stability": 0,
        "growth": 0,
        "control": 0,
        "adaptability": 0
      },
      "innate_self_axes": {
        "autonomy": 0,
        "connection": 0,
        "stability": 0,
        "growth": 0,
        "control": 0,
        "adaptability": 0
      }
    },
    "per_axis": {
      "autonomy": {
        "current": 0,
        "innate": 0,
        "delta": 0,
        "abs_delta": 0,
        "primary_pattern": "alignment",
        "growth_opportunity": false
      }
    },
    "overall_severity": "low",
    "max_abs_delta": 0,
    "summary_counts": {
      "alignment": 0,
      "suppression": 0,
      "overadaptation": 0,
      "energy_leakage": 0,
      "moderate_gap": 0,
      "growth_opportunity": 0
    },
    "aggregated": {
      "alignments": [],
      "suppressions": [],
      "overadaptations": [],
      "energy_leakages": [],
      "growth_opportunities": [],
      "moderate_gaps": []
    },
    "free_preview": {
      "radar_current": {},
      "radar_innate": {},
      "delta_by_axis": {}
    },
    "meta": {
      "rules_version": "v1",
      "calculated_at": ""
    }
  }
}
```

### `primary_pattern` enum (per axis)

```text
alignment | suppression | overadaptation | energy_leakage | moderate_gap
```

### `overall_severity` enum

```text
low | moderate | high
```

### `aggregated` item shape

Each list entry:

```json
{
  "axis": "stability",
  "delta": -16,
  "abs_delta": 16,
  "primary_pattern": "suppression"
}
```

`growth_opportunities` entries may include `growth_opportunity: true` on the per-axis object; list items follow the same axis/delta fields.

### Regeneration

If `CurrentSelfProfile` or `InnateSelfProfile` changes, regenerate `gap_profile` only. Birth data recalculation is not required.

# Interpretation Storage Principle

The following outputs are **not** persisted as source of truth:

* `gap_analysis` (03A LLM)
* `deep_pattern`, `deep_narrative`, `deep_self_report`, `deep_self_report_ui` (03B–03E)
* Other Human Meaning Engine / Report Generation outputs

These represent interpretation logic rather than source data.

Interpretation logic may evolve over time as:

* Interpretation Rules improve
* Signal Mapping improves
* Narrative Generation improves
* Prompt Engineering improves
* AI Models improve

Therefore these outputs should be generated dynamically rather than permanently stored.

### Persistent / regenerable layers

| Layer | Persist? | Notes |
|-------|----------|-------|
| Raw Saju | ✓ immutable | Birth data |
| Extended NormalizedSaju | ✓ | Calculation only |
| InnateSelfProfile | ✓ regenerable | From mapping rules |
| CurrentSelfProfile | ✓ | Survey output — [04_Survey_Output_Schema.md](../survey/04_Survey_Output_Schema.md) |
| `gap_profile` | Optional cache | Deterministic; regenerate from Current + Innate |

This allows future improvements without requiring recalculation of birth data.

Flow:

```text
Raw Saju

↓

Extended NormalizedSaju

↓

InnateSelfProfile

↓

CurrentSelfProfile + InnateSelfProfile

↓

gap_profile  (Rules — may cache)

↓

(Generated Dynamically)

gap_analysis, deep_pattern, deep_narrative, deep_self_report, deep_self_report_ui
```

---

# Storage Principle

Raw Saju must always be preserved.

Extended NormalizedSaju must always be preserved.

InnateSelfProfile can be regenerated.

`gap_profile` can be regenerated from `CurrentSelfProfile` + `InnateSelfProfile`.

`gap_analysis` and other LLM interpretation outputs should not be stored as immutable records.

---

# Regeneration Rule

If Human Framework Mapping changes:

```text
Raw Saju

↓

Extended NormalizedSaju
```

must remain unchanged.

Only:

```text
InnateSelfProfile
```

should be regenerated.

---

If interpretation logic changes:

```text
07_Saju_Deep_Interpretation_Rules

08_Self_Analysis_Signal_Mapping

09_Deep_Self_Report_Generation_Rules
```

should be regenerated dynamically.

No recalculation of birth data should be required.

---

# Design Principles

1. Raw Saju is immutable.
2. Extended NormalizedSaju stores calculations only.
3. InnateSelfProfile stores Human Framework scores.
4. `gap_profile` stores deterministic comparison signals only (no LLM prose).
5. `gap_analysis` and Deep report objects are generated dynamically (LLM).
6. Future expansion must not require recalculation of birth data.
7. Fast and Deep analysis share the same data source.
8. Relationship analysis reuses the same stored data.
9. Human Meaning and Narrative layers are not persistent source data.
10. Improvements to interpretation logic should not require database migration.
