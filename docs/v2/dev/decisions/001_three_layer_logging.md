# 001 — 개발 기록 3층 구조

**날짜:** 2026-06-25  
**상태:** 확정

---

## 배경

문서·프롬프트를 수정하다 보면 context가 흐려지고, 무엇이 바뀌었는지 추적이 어려웠다.  
반면 모든 것을 한 파일에 적으면 파일이 무거워져 개발이 어려워질 수 있다.

---

## 선택지

### A. 모든 것을 daily에 상세 기록

- 장점: 복기 쉬움
- 단점: 파일 비대, 정본과 혼동

### B. 개발 끝나면 로그 전부 삭제

- 장점: 폴더 가벼움
- 단점: 결정 이유·맥락 영구 손실

### C. 정본 / 작업중 / 일지 3층 + 주간 압축

- 장점: 가볍고 context 유지, 시행착오만 정리 가능
- 단점: 주 1회 정리 습관 필요

---

## 결정

**선택:** C

**이유:** 정본 문서는 구조만 유지하고, daily는 짧게, 중요한 이유는 decisions에 남긴다. Git은 diff 추적을 담당한다.
