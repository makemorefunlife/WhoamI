## 배운 점 / 결정

- `builders` 배열 순서 ≠ 화면 순서 — 실제로는 `CANONICAL_CHAPTER_DEFINITIONS`(하드코딩 특수 블록과 id로 결합) 아니면 `CHAPTER_GROUPS`(폴백) 둘 중 하나가 최종 화면 순서를 결정. 섹션 순서를 바꾸는 작업은 세 레이어(빌더 배열 + 두 챕터 구조) 전부 확인해야 함.
- 챕터 구조 재배치는 `id`를 바꾸지 않고 배열 "위치"와 "number" 표시값만 바꾸면, 별도 엔진(`buildCanonicalMarriageStoryPlan.ts`)이나 하드코딩된 `cDef.id === "..."` 특수 블록을 안 건드리고도 안전하게 순서를 바꿀 수 있음 — id 리네이밍은 절대 금지.
- 여러 세션이 같은 워킹 디렉토리를 동시에 쓸 때는 작업 시작 전 상대방이 지금 뭘 하고 있는지 먼저 확인하는 게 안전.
